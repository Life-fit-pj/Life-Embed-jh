## 대화에서 거주 선호를 기억해 다음 대화에 반영 — 2026-10-14

- **왜**: 채팅은 질문마다 처음부터 시작했다. 회원이 "전세 3억, 강남역 출퇴근"이라고 말해도
  다음 방문에서는 다시 말해야 했다.
- **무엇을**
  - `app/engine/memory.py` — 질문에서 선호 5칸(예산·거래유형·통근지·중요 지표·기피 조건)을 뽑는다.
    Structured Outputs(`output_config.format` JSON Schema, `app/ai/llm.py` 의 `ask_json`)로 모양을 강제하고,

    `merge()` 는 새로 말한 칸만 덮는다 — 말하지 않은 칸은 옛 기억을 지킨다.
  - `app/models/memory.py` — `user_memory` 표(회원 한 명에 한 줄). `py -m pipeline.migrate_user_memory` 로
    이 표만 만들고 RLS 를 켠다(기존 표는 건드리지 않는다).
  - 저장: `POST /chat` 이 답을 돌려준 **뒤** 백그라운드로 뽑아 저장한다(`app/api/chat.py`) — 답이 늦어지지 않는다.
  - 주입: 다음 대화의 generate 노드가 한 줄(최대 200자)로 싣는다(`app/graph/nodes.py`).
    "동네 데이터처럼 인용하지 말 것"을 같이 붙인다. 도구 경로와 재료 경로 둘 다에 실린다.
  - 회원만 — 손님(기기 번호)은 저장하지 않는다. Life-Web 은 로그인 토큰으로 확인한 회원 번호만 엔진에 넘기므로
    남의 번호를 적어 보내 남의 기억을 읽거나 쓸 수 없다. 회원 탈퇴 시 같이 지운다.
  - 마이페이지 "AI가 기억한 선호" 탭에서 보고 모두 지울 수 있다(Life-Web `routers/memory.py`).
  - 테스트 `tests/test_memory.py` — 스키마, 말하지 않은 값은 비어 있음, 잘못된 값 버림, 합치기 규칙, 주입 길이 상한, 채점.

### 측정

`py -m pipeline.golden_memory` — `data/golden/memory.csv` 대화 15개(질문 25개).
선호를 말한 대화 10개(그중 4개는 여러 턴에 나눠 말함, 1개는 말을 바꿈) + 선호가 없는 대화 5개
(동네 질문 · 다른 사람 이야기). 대화마다 실제 경로처럼 질문마다 뽑고 합친 마지막 기억을 정답과 칸 단위로 견준다.
모델 Claude Haiku 4.5(`claude-haiku-4-5-20251001`), 1회 실행.

틀린 2칸

| 대화 | 기대 | 실제 | 판단 |
|---|---|---|---|
| "…시끄러운 곳은 별로예요" | 기피 `소음` | 기피 `시끄러운 곳` | 뜻은 맞다. 채점이 글자를 봐서 틀린 것으로 셌다. 채점 기준은 고치지 않았다 |

본 것처럼 과적합이 된다. 기준선으로 남긴다.

### 재방문 예시 (회원 번호 C999999, 시험용 · 끝나고 지움)

1. 첫 방문: "아이가 초등학생이라 교육이 제일 중요하고, 전세 4억 안쪽으로 보고 있어요. 언덕은 싫어요"
   → 저장된 기억 `예산 4억 · 전세 · 중요 교육 · 피함 언덕`
2. 재방문(앞 대화 없음): "이 중에 어디가 제일 나을까요?"
   - 회원: 전세 시세를 예산과 견주고 학원 수를 근거로 한 동네를 골라 줬다
   - 같은 질문, 손님: "어떤 조건을 가장 우선하는지 말씀해 주시면…" 이라고 되물었다

### 채팅창에서 기억이 보이게 (2026-10-14)

기억을 몰래 쓰면 사용자는 "예산 말 안 했는데 왜 4억 기준이지?" 하고 헷갈린다. 쓰고 있다는 게 보이고 그 자리에서 고칠 수 있게 했다.

- **기억하는 조건 띠**: 회원이 채팅창을 열면 맨 위에 `[예산 4억 ✕] [전세 ✕] [피함 언덕 ✕]`. ✕ 는 그 조건 하나만 지운다
  (`DELETE /memory/{id}?field=avoid&value=언덕`, `chat_service.forget()`). 다 지우면 줄째 지운다.
  기억이 없으면 "말하면 기억해 둘게요" 를 보여 준다. 손님에게는 띠가 없다.
- **답 아래 반영 표시**: `POST /chat` 이 `memory`(이번 답에 실은 기억 한 줄)를 같이 돌려주고, 화면이 말풍선 아래에
  `↳ 기억한 조건 반영: 예산 4억 · 전세` 로 보여 준다.
- 기억은 답을 보낸 뒤에 저장되므로 화면은 답이 온 5초 뒤에 띠를 다시 읽는다. 저장이 더 늦으면 다음 답 때 보인다.
- 확인: C999999 로 첫 질문(memory 빈 글자) → 저장 → 두 번째 질문 memory `예산 4억 · 전세 · 중요 교육 · 피함 언덕`
  → ✕ 언덕 · ✕ 예산 각각 그 칸만 사라짐 → 손님은 memory 빈 글자. 테스트: 엔진 `tests/test_memory_forget.py` 4개,
  웹 `tests/test_smoke.py` 2개 추가.
- 기억하는 것은 **선호(사실)** 뿐이다. 지난 대화를 골라 이어 하는 기능(대화 묶음·그때의 동네 목록 저장)은 하지 않았다.

### 남은 것

- 질문마다 Claude 를 1번 더 부른다(회원만, 답을 준 뒤라 대기 시간은 안 는다). 선호가 없는 질문이 대부분이라
  싼 규칙으로 먼저 거르면 호출을 줄일 수 있다 — 아직 재지 않았다.
- 표본이 작다(15대화). 지어낸 칸 1개가 우연인지는 문항을 늘려야 안다.
- "예산 상관없어"처럼 **지우라는 말**은 처리하지 않는다. 지우기는 채팅창 띠의 ✕ 와 마이페이지에서 된다.
- 기억을 실은 뒤 답이 실제로 좋아졌는지는 재지 않았다(예시 1건뿐). 답 품질 평가는 LLM-as-a-Judge 가 필요하다.
